4. באמצעות תקשורת רשת, למשל בקשות HTTP ל־API של המיקרו־סרביס השני.
5. א
6. כי הסטטיסטיקות אמורות לקבל רק את הנתונים הדרושים להן או להשתמש בממשק של שירות אחר, ולא להתחבר ישירות למסד הנתונים עם הסיסמה שלו.
7. ניהול ותחזוקה מורכבים יותר, כי צריך לפרוס, לנטר ולתחזק כמה שירותים נפרדים.
8. Image היא תבנית שממנה יוצרים Container. Container הוא מופע רץ של אותה תמונה.

10. ב
11. זה הפורט במחשב המארח שאליו פונים מבחוץ; הוא ממופה לפורט 80 בתוך הקונטיינר.
12. ב
13. כדי ששינוי בקוד לא יגרום להתקנה מחדש של התלויות בכל build, כל עוד `requirements.txt` לא השתנה. כך Docker יכול להשתמש ב־cache.
14. כדי שהשרת יהיה נגיש גם דרך ממשק הרשת של הקונטיינר ולא רק מתוך הקונטיינר עצמו.
15. כדי להימנע מהכנסת סודות לקוד ובכך לצמצם חשיפה שלהם; משתני סביבה מאפשרים להגדיר אותם בנפרד.
16. ייתכן שהשירות תלוי בשירות אחר שאינו זמין או שכתובת החיבור אליו שגויה. `/health` בודק שהשירות עצמו חי, ואילו `/stats` עשוי להיכשל כשהתלות אינה זמינה.
17. `docker stop` עוצר קונטיינר רץ. `docker rm` מוחק קונטיינר שנעצר, אך לא את ה־image שלו.
18. Docker הוריד את התגית `latest` כברירת מחדל. בסרוויס אמיתי עדיף לציין גרסה מדויקת כדי לקבל build צפוי ועקבי.
